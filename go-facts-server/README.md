# Сервер фактов

Календарь перестаёт возить факты в бандле. Сервер хранит базу фактов в Postgres, отдаёт факты на дату с ETag, отдаёт всё, что изменилось после ревизии N, принимает правки по токену. Импорт из `facts.json`, который делает сборщик. В календаре появляется удалённый репозиторий фактов: при запуске тянет дельту, сливает в локальное хранилище, офлайн работает из него.

## Зачем

Второй сервис на Go по скелету первого, чтобы увидеть, что переиспользуется. Новое: HTTP-кэширование через ETag, дельта-синк с ревизиями и надгробиями, защищённая запись. И впервые я делаю обе стороны: сервер и клиент, и вижу, как решения на одной стороне отзываются на другой.

## Что будет в первой версии

- `GET /v1/facts/{MM-DD}` с ETag и `If-None-Match`.
- `GET /v1/facts/random?date=MM-DD`.
- `GET /v1/facts?since=N` дельта: новые, изменённые, удалённые с ревизией.
- `POST`, `PUT`, `DELETE /v1/facts/{id}` по токену администратора.
- `factsctl import facts.json` идемпотентно.
- Postgres, миграции, ревизия на каждую запись, надгробия.
- Docker Compose, CI, как в сокращалке.
- Календарь: `RemoteFactRepository`, слияние дельты в локальное хранилище, `If-None-Match`, фоновая синхронизация при запуске.

## Готово, когда

- Календарь на чистом устройстве получает всю базу с сервера за один запрос дельты и дальше работает офлайн.
- Правка факта на сервере доезжает до календаря при следующем запуске, удаление тоже.
- `If-None-Match` даёт 304 и не гоняет тело.
- Ревизия монотонна под параллельной записью, проверено тестом.
- Токен не подбирается перебором за разумное время: сравнение постоянного времени, ограничение частоты.
- В `docs/NOTES.md` список того, что переехало из сокращалки без изменений, и что пришлось поменять.

## Что хочу попробовать

ETag и условные запросы, дельта-синк с ревизиями и надгробиями, идемпотентный импорт, авторизация токеном с `subtle.ConstantTimeCompare`, ограничение частоты на запись, `BIGSERIAL` как ревизия и его подводные камни, на стороне Swift: слияние дельты, локальное хранилище фактов, фоновая задача при запуске.

## Как начать

1. Прочитать `docs/SPEC.md` и `docs/ARCHITECTURE.md`.
2. Пробежать `docs/STACK.md`. Раздел «что почитать» смотреть перед соответствующей фазой, не всё сразу.
3. Открыть `docs/PLAN.md` и идти по фазам, отмечая чекбоксы. Агента звать только там, где стоит 🤖.
4. Заметки, решения и вопросы складывать в `docs/NOTES.md`.
