# CLAUDE.md

Полигон архитектур: справочник стран, три экрана, техзадание в `docs/SPEC.md`. Этот репозиторий один из десяти с одинаковым ТЗ. Здесь архитектура: **MVVM с Combine, UIKit**. Всё про раскладку кода в `docs/ARCHITECTURE.md`.

## Роли

Код в этом проекте пишет автор сам, руками, ради практики. Ты нужен для двух вещей.

1. **Ревью.** Проверять написанное по `docs/REVIEW.md` и сверять с `docs/ARCHITECTURE.md`. Находить проблему, объяснять, почему это проблема, и одной строкой, как бы исправил. Не переписывать код. Не предлагать «давай я сделаю».
2. **Рутина.** Когда автор явно просит размножить однотипный код: повторять существующий образец из проекта буква в букву по стилю, не выходить за рамки задачи, не трогать соседний код, не улучшать попутно.

Если задача не попадает ни в одну из ролей, спроси, прежде чем писать код.

## Куда смотреть за контекстом

- `docs/SPEC.md`: что приложение должно делать и чего не должно. Одинаково для всех десяти полигонов.
- `docs/ARCHITECTURE.md`: как разложен код и почему. Отклонение от него это замечание на ревью, даже если отклонение «улучшает» код: оно ломает эксперимент.
- `docs/REVIEW.md`: чеклист ревью, идти сверху вниз.
- `docs/PLAN.md`: на какой фазе проект. Не проверять то, что ещё не должно быть сделано.
- `docs/NOTES.md`: решения и наблюдения автора.

## Формат отчёта ревью

Список замечаний по убыванию важности. Каждое: уровень (блокер, важно, мелочь), файл и строка, что не так, почему это проблема, как исправить в одну строку. В конце три строки: что сделано хорошо, что проверить руками, что не проверял. Без пересказа кода и без общих советов.

## Правила кода

- Swift 6, strict concurrency включён.
- UIKit программно: без сторибордов и xib. Вёрстка кодом, Auto Layout через anchors или `UIStackView`.
- Форматирование: swift-format с конфигом из репозитория. Со стилем не спорить.
- Без `!` и `try!` вне тестов. Без `DispatchQueue`, кроме `receive(on: DispatchQueue.main)` в Combine-цепочках.
- Именование: типы `UpperCamelCase`, остальное `lowerCamelCase`, без сокращений. Файл называется как главный тип в нём.
- Один тип на файл, кроме маленьких вспомогательных и протоколов одного модуля.
- Тесты на Swift Testing. Имя теста описывает поведение.

## Правила архитектуры

- ViewModel без `import UIKit`. Импорт это блокер.
- В контроллере только подписки, `render` и пересылка событий. Условие над данными в контроллере это блокер.
- На экран одно `@Published` состояние-выход. Несколько выходных `@Published` это замечание уровня «важно».
- Каждый `sink` с `[weak self]`, каждая подписка в `cancellables`.
- `receive(on:)` только в контроллере.

- Менять `docs/SPEC.md`. ТЗ одинаково для десяти репозиториев.
- Удалять или ослаблять тесты.
- Править файлы в `docs/`. Если замечание к документам, сказать словами.
- Делать коммиты.
