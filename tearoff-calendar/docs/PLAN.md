Цель: пустой проект, который собирается, с пакетом и тестами.

- [ ] Xcode-проект `TearoffCalendar`: iOS, SwiftUI, Swift 6, strict concurrency complete.
- [ ] Локальный пакет `Packages/CalendarCore` с пустым таргетом и одним тестом-заглушкой.
- [ ] Пакет подключён к приложению.
- [ ] `.swift-format` в корне, форматирование прогнано.
- [ ] `.gitignore` для Xcode, первый коммит.
- [ ] Структура папок из `ARCHITECTURE.md` создана, пустые файлы допустимы.

Вопросы себе: чем локальный пакет отличается от папки в проекте? Что делает `swift test` без Xcode?

Готово, когда `swift test` в папке пакета зелёный, а приложение запускается с пустым экраном.

## Фаза 1. Ядро без интерфейса

Цель: вся логика дат и фактов, покрытая тестами, без единого `import SwiftUI`.

- [ ] Модели `Fact`, `CalendarPage`, `Settings`.
- [ ] `DateEngine` с `Calendar` в init: next, previous, startOfToday, monthDayKey.
- [ ] Тесты DateEngine: 31 декабря, 28 февраля в високосный и невисокосный год, смена пояса.
- [ ] Протокол `FactRepository`, `InMemoryFactRepository` для тестов.
- [ ] `BundleFactRepository` с чтением `facts.json`. Файл с десятком дат, третье сентября обязательно.
- [ ] Протоколы `PageStore`, `SettingsStore` и реализации на `UserDefaults` с suiteName.
- [ ] `FactPicker` с внедрённым генератором случайных чисел. Тесты: повторный выбор той же даты даёт тот же факт; пустой день даёт nil.

Вопросы себе: почему `Date` нельзя считать днём? Как тест подсовывает фиксированный часовой пояс? Зачем `FactPicker` принимает генератор случайных чисел?

Готово, когда тесты покрывают все ветки DateEngine и FactPicker и `swift test` зелёный.

🤖 Ревью по `REVIEW.md`, разделы «Ядро» и «Даты».

## Фаза 2. Статичный экран

Цель: страница выглядит как задумано, без жестов.

- [ ] `PageView`: число, месяц, день недели, год, факт. Только вёрстка, данные приходят параметрами.
- [ ] Превью `PageView` для трёх случаев: обычный день, длинный факт, нет факта.
- [ ] `CalendarViewModel` с текущей страницей и подложкой следующей.
- [ ] `CalendarView` показывает две страницы стопкой, кнопку «Сегодня» и индикатор «не сегодня».
- [ ] Сборка зависимостей в `TearoffCalendarApp`.
- [ ] Dynamic Type: проверить самый большой размер, ничего не обрезается.

Вопросы себе: когда SwiftUI перерисовывает вью с `@Observable`, а когда нет? Почему `PageView` не должен знать про ViewModel?

Готово, когда на устройстве видна сегодняшняя страница с фактом.

## Фаза 3. Жесты и анимация

Цель: отрыв и возврат ощущаются как бумага.

- [ ] `TearGesture`: перетаскивание с прогрессом от 0 до 1, прогресс в ViewModel.
- [ ] До порога страница возвращается spring-анимацией, после порога улетает, подложка становится текущей.
- [ ] Свайп вниз возвращает предыдущую страницу.
- [ ] Прерываемость: новый жест во время анимации не ломает состояние. Проверить руками: быстро дёрнуть десять раз.
- [ ] Отклик `sensoryFeedback` при срыве.
- [ ] Уважать «Уменьшение движения»: вместо полёта простое затухание.

Вопросы себе: почему `@GestureState` не подошёл? Чем spring-анимация с duration и bounce отличается от старых? Что происходит с анимацией, когда состояние меняется посередине?

Готово, когда десять быстрых свайпов подряд не дают рассинхрона между датой и картинкой.

🤖 Ревью, разделы «Состояние» и «Жесты».

## Фаза 4. Состояние, хранение, настройки

Цель: приложение помнит страницу и умеет прыгать по датам.

- [ ] Сохранение текущей страницы в `PageStore` при каждом изменении.
- [ ] Восстановление при запуске с учётом настройки «показывать сегодня».
- [ ] Повреждённое состояние: сброс на сегодня без краша, тест.
- [ ] Выбор даты по тапу, границы 1900…2100.
- [ ] `DayChangeObserver`: смена дня при открытом приложении и при возврате из фона обновляет индикатор.
- [ ] Экран настроек с тремя пунктами и разделом «О приложении».

Вопросы себе: чем `NSCalendarDayChanged` отличается от проверки при `scenePhase == .active`? Где граница между ViewModel настроек и `SettingsStore`?

Готово, когда после убийства приложения и повторного запуска страница та же.

## Фаза 5. Уведомление

Цель: третьего сентября приходит пуш.

- [ ] `NotificationScheduler`: запрос разрешения по тумблеру, не при запуске.
- [ ] Ежегодный триггер на третье сентября в выбранное время.
- [ ] Смена времени перепланирует, выключение удаляет.
- [ ] Отказ в разрешении: тумблер назад, подсказка про системные настройки.
- [ ] Тап по пушу открывает страницу третьего сентября.
- [ ] Проверка на устройстве: временно поставить триггер на «через две минуты», убедиться, вернуть.

Вопросы себе: почему в компонентах триггера нет года? Что будет, если разрешение отозвать в системных настройках после планирования?

Готово, когда пуш пришёл на реальное устройство при закрытом приложении.

## Фаза 6. Виджет

Цель: виджет показывает сегодня и переключается в полночь сам.

- [ ] Таргет виджета, подключён `CalendarCore`, App Group настроен для обоих таргетов.
- [ ] `CalendarTimelineProvider`: записи на сегодня и завтра, обновление после полуночи.
- [ ] Вёрстка small и medium.
- [ ] Deep link: тап открывает сегодняшнюю страницу.
- [ ] Факт в виджете совпадает с фактом в приложении.
- [ ] Проверка: поставить системное время на 23:59, дождаться.

Вопросы себе: сколько времени есть у провайдера? Что произойдёт, если приложение поменяет факт, пока виджет уже показан?

Готово, когда виджет сутки на экране без запуска приложения показывает верную дату.
