# Спецификация

## Одним абзацем

Бот отвечает на команды и сам присылает напоминания. Расписание берёт из источника по настройке, кэширует, обновляет раз в интервал. Подписки хранит в SQLite. Один процесс, long polling.

## Команды

| Команда | Ответ |
|---|---|
| `/start`, `/help` | Список команд и текущий источник |
| `/next` | Ближайшее событие: что, когда в поясе пользователя, через сколько |
| `/today` | Все события до конца дня пользователя |
| `/subscribe 30` | Напоминать за 30 минут. Допустимо 5…120. Без числа: 15 |
| `/unsubscribe` | Отключить |
| `/tz Europe/Moscow` | Часовой пояс пользователя, проверка по базе поясов. По умолчанию UTC |
| `/source` | Какой источник настроен на сервере. Менять нельзя, это настройка развёртывания |

Неизвестная команда: подсказка `/help`. Ошибки человеческим языком.

## Источники

Интерфейс:

```
type Event struct { ID string; Title string; Start, End time.Time; Details string }
type Source interface {
    Name() string
    Fetch(ctx context.Context) ([]Event, error)   // события на ближайшие сутки и дальше, в UTC
}
```

**Splatoon 3.** `https://splatoon3.ink/data/schedules.json`. Ротации по два часа: режимы для Anarchy и Regular, карты. Событие: «Anarchy: Tower Control на картах X, Y» с началом ротации. Salmon Run отдельным событием. Если сервис недоступен или закрыт, источник отдаёт ошибку, бот работает из кэша.

**Формула-1.** Jolpica, расписание сезона, сессии уикенда как события. Формат как в `f1-kit`.

Обновление: раз в 10 минут для Splatoon, раз в 6 часов для F1. Интервал задаёт источник. Ошибка обновления: кэш остаётся, лог, повтор через минуту с ростом до интервала.

## Напоминания

- Планировщик раз в 30 секунд: для каждого подписчика и каждого события, если `start - N минут` в окне [сейчас, сейчас + 30с] и напоминание ещё не отправлено, отправить.
- Отправленные: таблица `sent` с `chat_id, event_id`, чтобы после перезапуска не повторять.
- Пропущенные во время простоя: если бот был выключен и `start - N` уже в прошлом, но событие ещё не началось, отправить одно напоминание «скоро». Если событие прошло, не отправлять.
- Текст: «Через 30 минут: Tower Control на Museum d'Alfonsino. Начало в 18:00».

## Хранение

SQLite, файл в томе. Таблицы: `user (chat_id, tz, remind_minutes, subscribed)`, `sent (chat_id, event_id, sent_at)`. Миграции при старте простым списком SQL.

## Конфигурация

`BOT_TOKEN` обязателен, `SOURCE` (`splatoon` или `f1`), `DB_PATH`, `LOG_LEVEL`, `POLL_TIMEOUT`.

## Жизненный цикл

- Старт: конфиг, база, миграции, первый `Fetch` (ошибка не блокирует старт), запуск горутин: опрос Telegram, обновление источника, планировщик.
- `SIGTERM`: отмена контекста, горутины завершаются, `WaitGroup`, база закрывается, до 10 секунд.

## Границы

- Пользователь в поясе с переходом на летнее время: `time.Location` учитывает.
- Событие длиннее суток: `/today` показывает, если началось сегодня.
- Два события одновременно: оба напоминания одним сообщением.
- Telegram отвечает 429: библиотека ждёт `retry_after`, планировщик не теряет напоминание.
- Пользователь заблокировал бота: ошибка отправки, подписка отключается с логом.
- База заблокирована: SQLite с `busy_timeout`.

## Не делаем

- Вебхуки.
- Групповые чаты сверх личных.
- Смену источника из чата.
- Несколько источников одновременно.
