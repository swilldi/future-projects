# План

Фазы идут по порядку. Каждая заканчивается рабочим состоянием и коммитом. «Вопросы себе» это то, на что я должен уметь ответить после фазы, не заглядывая в документацию. Не могу ответить, значит фаза не закончена.

Где звать агента, отмечено значком 🤖. В остальных местах не звать.

## Фаза 0. Каркас

Цель: пустой проект, который собирается.

- [ ] iOS App, жизненный цикл через App Delegate и Scene Delegate, программный UI без сториборда.
- [ ] `.swift-format` в корне, `.gitignore` для Xcode, первый коммит.
- [ ] Папки из `ARCHITECTURE.md` созданы, пустые файлы допустимы.
- [ ] `SceneDelegate` собирает вкладки, модули создаются билдерами.

Готово, когда приложение запускается с пустым экраном.

## Фаза 1. Сервисы

Цель: сеть, кэш, избранное, без экранов. Если это не первый полигон, скопировать `Services/` и `Models/` из предыдущего и только прогнать тесты.

- [ ] `CountryDTO`, `Country`, маппинг.
- [ ] `CountriesAPI` с параметром `fields`.
- [ ] `CountryCache` в Caches, `FavoritesStore` в Documents с потоком `changes`.
- [ ] Тесты: маппинг стран без столицы и с несколькими столицами; повреждённый файл даёт пустое значение; `changes` доставляет новое значение после `save`.

Вопросы себе: почему DTO и `Country` разделены? Что случится, если API добавит поле? Почему кэш в Caches, а избранное в Documents?

Готово, когда тесты сервисов зелёные.

## Фаза 2. Список

Цель: экран списка с кэшем и загрузкой из сети.

- [ ] `CountriesListContracts` с двумя протоколами и `CountryRow`.
- [ ] `CountriesListPresenter`: кэш, загрузка, `display(rows:)`, `displayLoading`, `displayError`.
- [ ] `CountriesListViewController`: реализует протокол, diffable snapshot из `CountryRow`.
- [ ] `CountriesListBuilder`.

Вопросы себе: почему презентер отдаёт `CountryRow`, а не `Country`? Что сломается, если контроллер сам отформатирует столицу?

Готово, когда список стран виден на устройстве и с кэшем, и без.

## Фаза 3. Детали и избранное

Цель: детали, кнопка избранного, экран избранного, синхронизация между экранами.

- [ ] Модуль деталей: презентер держит `Country`, слушает `changes`, командует состоянием кнопки.
- [ ] Модуль избранного по образцу списка.
- [ ] Навигация: презентер вызывает `navigateToDetail`, контроллер строит модуль через билдер и пушит. Записать, как это ощущается.

Вопросы себе: кто должен знать о `UINavigationController` в MVP? Какие варианты и чем плох каждый?

Готово, когда избранное меняется во всех трёх экранах сразу и переживает перезапуск.

## Фаза 4. Поиск, обновление, состояния

Цель: все состояния из `SPEC.md` воспроизводятся руками.

- [ ] Поиск: контроллер пересылает текст, презентер фильтрует и командует.
- [ ] Обновление: `didPullToRefresh` в презентере, перезапись кэша.
- [ ] Все состояния из `SPEC.md`. Проверить, что после каждой ошибки индикатор загрузки спрятан.

Вопросы себе: сколько методов стало в view-протоколе? Какие из них можно было бы схлопнуть в одно «состояние»?

Готово, когда отключение сети, повреждённый кэш и пустой поиск дают ровно то, что в спецификации.
