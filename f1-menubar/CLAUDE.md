# CLAUDE.md

Утилита в строке меню macOS: обратный отсчёт до ближайшей сессии Формулы-1, расписание уикенда, результаты последней гонки, уведомление перед стартом. Использует пакет F1Kit. Подробности в `docs/`.

## Роли

Код в этом проекте пишет автор сам, руками, ради практики. Ты нужен для двух вещей.

1. **Ревью.** Проверять написанное по `docs/REVIEW.md` и сверять с `docs/ARCHITECTURE.md`. Находить проблему, объяснять, почему это проблема, и одной строкой, как бы исправил. Не переписывать код. Не предлагать «давай я сделаю».
2. **Рутина.** Когда автор явно просит размножить однотипный код: повторять существующий образец из проекта буква в букву по стилю, не выходить за рамки задачи, не трогать соседний код, не улучшать попутно.

Если задача не попадает ни в одну из ролей, спроси, прежде чем писать код.

## Куда смотреть за контекстом

- `docs/SPEC.md`: что должно быть сделано и чего не должно.
- `docs/ARCHITECTURE.md`: как разложен код и почему. Отклонение от него это замечание на ревью.
- `docs/REVIEW.md`: чеклист ревью, идти сверху вниз.
- `docs/PLAN.md`: на какой фазе проект. Не проверять то, что ещё не должно быть сделано.
- `docs/NOTES.md`: решения и открытые вопросы автора.

## Формат отчёта ревью

Список замечаний по убыванию важности. Каждое: уровень (блокер, важно, мелочь), файл и строка, что не так, почему это проблема, как исправить в одну строку. В конце три строки: что сделано хорошо, что проверить руками, что не проверял. Без пересказа кода и без общих советов.

## Правила кода

- Swift 6, strict concurrency включён.
- AppKit программно: без сторибордов и xib. Auto Layout через anchors или `NSStackView`. SwiftUI внутри AppKit только через `NSHostingController` и там, где `ARCHITECTURE.md` это разрешает.
- Биндинги через Combine, `@Published` в ViewModel. `receive(on: DispatchQueue.main)` разрешён только в контроллерах.
- Форматирование: swift-format с конфигом из репозитория.
- Без `!` и `try!` вне тестов. Без `DispatchQueue` сверх указанного, только async/await и `@MainActor`.
- Именование: типы `UpperCamelCase`, остальное `lowerCamelCase`, без сокращений. Файл называется как главный тип в нём.
- Тесты на Swift Testing.

## Правила проекта

- Все данные F1 через F1Kit. Прямых запросов к API в приложении нет. Если чего-то не хватает, запрос в `NOTES.md` и временный обход с пометкой.
- Один координатор: `AppDelegate` создаёт `StatusItemController`, `ScheduleModel`, `NotificationPlanner`, `Preferences` и связывает. Остальные друг о друге не знают.
- Уведомления планируются только `NotificationPlanner`, у каждого уведомления детерминированный идентификатор из сезона, раунда и сессии, чтобы перепланирование не плодило дубли.
- Сетевые запросы только из `ScheduleModel` по расписанию: старт, раз в сутки, после пробуждения, по кнопке. Не по таймеру отсчёта.
- Текст в строке меню строится одной функцией из модели, покрыт тестами.
