# Сокращалка ссылок: первый сервис на Go

Классический первый сервис: отдал длинную ссылку, получил короткую, перешёл по короткой, попал на длинную, счётчик вырос. Всё на стандартной библиотеке Go там, где она справляется, Postgres для хранения, Docker Compose, чтобы поднять одной командой. Цель не сокращалка, а Go: пакеты, интерфейсы, ошибки, контексты, тесты.

## Зачем

Go в планах давно, и первый проект должен быть банальным, чтобы всё внимание ушло на язык и его привычки: как раскладывать пакеты, как оборачивать ошибки, зачем везде контекст, как тестировать обработчики без базы и базу без обработчиков. Плюс Docker по-взрослому: многоэтапная сборка и крошечный образ.

## Что будет в первой версии

- `POST /api/links` создаёт короткую ссылку, `GET /{code}` редиректит и считает, `GET /api/links/{code}` отдаёт статистику, `GET /api/links` список, `DELETE /api/links/{code}` удаляет.
- Валидация URL, генерация кода из семи символов, обработка коллизий.
- Postgres через `pgx`, миграции через `goose` из встроенных файлов.
- Конфигурация из переменных окружения, структурные логи через `slog`, корректное завершение по сигналу.
- Тесты обработчиков через `httptest` с хранилищем в памяти, интеграционные тесты хранилища на настоящем Postgres в Docker.
- `Dockerfile` многоэтапный, `docker compose up` поднимает базу, миграции и сервис.
- GitHub Actions: `vet`, `golangci-lint`, тесты с `-race`, сборка образа.

## Готово, когда

- `docker compose up` на чистой машине поднимает всё, `curl` из README работает.
- `go test -race ./...` зелёный, интеграционные тесты идут против Postgres в контейнере.
- Образ меньше 20 мегабайт, работает не от root.
- Счётчик переходов не теряет инкременты под параллельной нагрузкой, проверено тестом с сотней горутин.
- В `docs/NOTES.md` список того, что в Go оказалось непривычным после Swift, и что понравилось.

## Как начать

1. Прочитать `docs/SPEC.md` и `docs/ARCHITECTURE.md`.
2. Пробежать `docs/STACK.md`. Раздел «что почитать» смотреть перед соответствующей фазой, не всё сразу.
3. Открыть `docs/PLAN.md` и идти по фазам, отмечая чекбоксы. Агента звать только там, где стоит 🤖.
4. Заметки, решения и вопросы складывать в `docs/NOTES.md`.
