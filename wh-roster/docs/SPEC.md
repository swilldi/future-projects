# Спецификация

## Одним абзацем

Три колонки: слева списки, в центре выбранный список с юнитами и итогом очков, справа выбранный юнит с размером и снаряжением или выбор отряда из справочника. На iPhone то же стеком. Справочник импортируется из JSON. Список экспортируется в PDF и JSON.

## Экраны

### Списки

- Все списки по дате изменения: имя, фракция, очки из лимита, предупреждения значком.
- Создать: имя, фракция из справочника, лимит 500, 1000, 2000 или своё.
- Свайп: удалить с подтверждением, дублировать.

### Список

- Заголовок: имя, фракция, детачмент, счётчик «1850 / 2000».
- Юниты по порядку: имя отряда, размер, снаряжение кратко, очки. Перетаскивание для порядка. Свайп: удалить, дублировать.
- Предупреждения списком под заголовком: «Превышен лимит на 50», «Более трёх Intercessor Squad», «Нет лидера».
- Кнопка «Добавить юнит» открывает выбор отряда справа.
- Заметки внизу.
- Тулбар: отмена, повтор, экспорт.

### Юнит

- Отряд, размер из допустимых, очки за размер.
- Снаряжение: группы опций с выбором одного или нескольких, ограничения «не больше N на отряд», очки за опцию.
- Итог очков юнита.
- Все изменения применяются сразу и отменяемы.

### Выбор отряда

- Поиск по имени, фильтр по ключевым словам (Infantry, Vehicle, Character).
- Список отрядов фракции с очками за минимальный размер.
- Тап добавляет юнит минимального размера в список и открывает его.

### Справочник и настройки

- Импорт JSON справочника: заменить или дополнить.
- Демо-фракция: кнопка «загрузить демо».
- Удалить справочник с подтверждением, списки на его основе остаются с замороженными данными.

## Правила

- Очки юнита: очки за размер плюс сумма опций.
- Очки списка: сумма юнитов.
- Предупреждения: превышение лимита; более трёх юнитов одного отряда, кроме помеченных как без ограничения; отсутствие хотя бы одного отряда с ключевым словом Character; опция превысила лимит на отряд.
- Предупреждения не блокируют сохранение.

## Формат справочника

```
{
  "factions": [{
    "id": "demo-order", "name": "Орден Демо",
    "detachments": ["Ударный клин"],
    "datasheets": [{
      "id": "demo-warriors", "name": "Воины Демо",
      "keywords": ["Infantry", "Battleline"],
      "sizes": [{"models": 5, "points": 80}, {"models": 10, "points": 160}],
      "wargear": [{
        "group": "Оружие сержанта", "select": "one",
        "options": [{"id": "sword", "name": "Меч", "points": 0}, {"id": "fist", "name": "Кулак", "points": 10}]
      }, {
        "group": "Тяжёлое", "select": "upTo", "max": 1, "perModels": 5,
        "options": [{"id": "hb", "name": "Тяжёлый болтер", "points": 5}]
      }],
      "unlimited": false
    }]
  }]
}
```

## Экспорт

- PDF: заголовок, таблица юнитов с размером, снаряжением, очками, итог, предупреждения, заметки. Шрифт системный, одна-две страницы.
- JSON списка: имя, фракция, лимит, юниты с идентификаторами отрядов и опций, заметки. Импорт того же формата.

## Границы

- Справочник обновлён, отряд в списке исчез: юнит помечен «устарел», очки замораживаются.
- Размер отряда изменился в справочнике: юнит хранит свой размер, предупреждение при несовпадении.
- Импорт битого JSON: ошибка с номером строки, база не тронута.
- Отмена после закрытия приложения: стек сбрасывается.
- Список без юнитов: экспорт PDF с пустой таблицей.

## Не делаем

- Правила отрядов, профили, способности. Только очки и состав.
- Синхронизацию.
- Готовые данные фракций.
- Печать напрямую. Через Файлы.

## Сущности CoreData

```
Faction 1 ──▶ N Datasheet 1 ──▶ N WargearGroup 1 ──▶ N WargearOption
Datasheet 1 ──▶ N SizeOption
Roster 1 ──▶ N RosterEntry N ──▶ 1 Datasheet (nullify при удалении)
RosterEntry 1 ──▶ N WargearSelection N ──▶ 1 WargearOption (nullify)
RosterEntry: order, models, frozenName, frozenPoints
```

Правила удаления: Faction → Datasheet cascade; Datasheet → RosterEntry nullify с заморозкой; Roster → RosterEntry cascade.
