# Сборщик фактов

На каждый из 366 дней сходить в Википедию, взять раздел «События» со страницы вида «3 сентября», вычистить разметку, отобрать короткие внятные факты с годом, выбрать до трёх на день детерминированно и записать в JSON той структуры, которую ждёт `tearoff-calendar`. С кэшем сырых ответов, паузой между запросами и атрибуцией по лицензии.

## Зачем

Календарю нужна база фактов, а писать 366 дней руками глупо. Python здесь как быстрый инструмент: один вечер, скрипт, результат. Заодно вспомнить `pathlib`, типы, `pytest` на фикстурах и как вежливо ходить в чужой API.

## Что будет в первой версии

- Загрузка вики-текста страницы дня через MediaWiki API, для всех 366 дней, с кэшем на диске.
- Разбор раздела «События»: год и текст.
- Чистка разметки: ссылки, шаблоны, курсив, сноски.
- Фильтр: есть год, длина от 40 до 200 символов, нет незакрытой разметки, не про смерть.
- Отбор до трёх на день, детерминированный по дате.
- Вывод `facts.json` по схеме календаря плюс статистика по дням без фактов.
- Флаги: дни, лимит на день, выходной файл, язык, без кэша.

## Готово, когда

- `facts.json` для всех 366 дней, у каждого дня хотя бы один факт или день в отчёте «пусто».
- Файл валиден по схеме и подхватывается календарём без правок.
- Повторный запуск не ходит в сеть благодаря кэшу и даёт тот же файл.
- Тесты чистки и фильтра зелёные на двадцати записанных строках разметки.
- Атрибуция Википедии и лицензии в выходном файле и в README календаря.

## Что хочу попробовать

`uv` для окружения, `httpx` с таймаутами и повтором, `mwparserfromhell` для разметки, `argparse`, `pathlib`, типы с `mypy`, `ruff`, `pytest` на фикстурах, `logging`, детерминированный выбор через `random.Random(seed)`.

## Как начать

1. Прочитать `docs/SPEC.md` и `docs/ARCHITECTURE.md`.
2. Пробежать `docs/STACK.md`. Раздел «что почитать» смотреть перед соответствующей фазой, не всё сразу.
3. Открыть `docs/PLAN.md` и идти по фазам, отмечая чекбоксы. Агента звать только там, где стоит 🤖.
4. Заметки, решения и вопросы складывать в `docs/NOTES.md`.
