# F1Kit: клиент к данным Формулы-1

Библиотека `F1Kit`: календарь сезона с сессиями в UTC, результаты гонок, личный и командный зачёт, удобная функция «следующая сессия от такого-то момента». Под капотом свой тонкий сетевой слой: описание эндпоинтов, клиент за протоколом, перехватчики для логов и ограничения частоты, повторы с задержкой. Всё тестируется без сети через подмену `URLProtocol`. Консольная команда `f1 next` как демонстрация и дымовой тест.

## Зачем

Проектировать библиотеку это не то же самое, что писать приложение: публичный API, который нельзя ломать, дженерики всерьёз, документация, версии. F1 как предметная область, потому что мне это интересно и потому что пакет потом кормит менюбар-утилиту. Заодно свой сетевой слой, чтобы понять, что делают Alamofire и подобные, не беря их.

## Что будет в первой версии

- `F1Client` с методами: расписание сезона, результаты гонки, личный зачёт, командный зачёт.
- `nextSession(after:)` по расписанию с учётом всех сессий уикенда.
- Модели `Sendable` и `Codable` с декодированием вложенного формата Ergast.
- `HTTPClient` протокол, реализация на URLSession, `Endpoint` как описание запроса.
- Перехватчики: логирование, ограничение частоты по правилам Jolpica.
- Повторы на 5xx и 429 с экспоненциальной задержкой и подменяемым «сном» для тестов.
- Ошибки с контекстом: путь ключа при ошибке декодирования, `Retry-After` при 429.
- Тесты на фикстурах через `URLProtocol`, без сети.
- DocC с обзором и одним туториалом. CI на GitHub Actions. Тег 0.1.0.
- Исполняемый таргет `f1` с командами `next`, `schedule`, `standings`.

## Готово, когда

- `swift test` зелёный на macOS и в Docker на Linux без сети.
- `f1 next` печатает следующую сессию в локальном времени с реального API.
- Публичный API документирован полностью, DocC собирается без предупреждений.
- Тег `0.1.0`, пакет подключается в другой проект по URL.
- Тест на повторы проходит мгновенно благодаря подменённому сну.
- В `docs/NOTES.md` список решений по публичному API с объяснением, почему так.

## Что хочу попробовать

Дизайн публичного API пакета, `Endpoint` с дженерик-ответом, протокол `HTTPClient`, перехватчики как цепочка, `Clock` и свой протокол сна для тестируемых задержек, `URLProtocol` в тестах пакета, DocC, семантические версии, сборка на Linux, `swift-argument-parser` в исполняемом таргете.

## Как начать

1. Прочитать `docs/SPEC.md` и `docs/ARCHITECTURE.md`.
2. Пробежать `docs/STACK.md`. Раздел «что почитать» смотреть перед соответствующей фазой, не всё сразу.
3. Открыть `docs/PLAN.md` и идти по фазам, отмечая чекбоксы. Агента звать только там, где стоит 🤖.
4. Заметки, решения и вопросы складывать в `docs/NOTES.md`.
