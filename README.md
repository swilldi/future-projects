# Заготовки пет-проектов

Библиотека проектов на будущее. Каждая папка это самодостаточная заготовка: идея, техзадание, архитектура, стек, план и чеклист ревью. Кода нет. Код пишется руками при старте проекта, агент зовётся на ревью и рутину.

## Как пользоваться

1. Выбрать проект из таблиц ниже.
2. Скопировать папку в отдельное место и сделать `git init`. Папка ничего не ждёт от соседей.
3. Прочитать `README.md` проекта, потом `docs/PLAN.md`. Идти по фазам.
4. Агента звать только там, где план это отмечает. `CLAUDE.md` в папке объясняет ему роль.
5. Вернуться сюда и обновить статус.

## Что внутри каждой папки

| Файл | Для кого | Что там |
|---|---|---|
| `README.md` | я | идея, зачем, что считается готовым, как начать |
| `CLAUDE.md` | агент | роль, формат ревью, правила кода, что нельзя |
| `docs/SPEC.md` | оба | требования, экраны, сущности, границы, что отложено |
| `docs/ARCHITECTURE.md` | оба | слои, папки, компоненты, поток данных, паттерны, грабли |
| `docs/STACK.md` | я | технологии, зачем каждая, что хочу понять, что почитать |
| `docs/PLAN.md` | я | фазы с чекбоксами, вопросы себе, где звать агента |
| `docs/REVIEW.md` | агент | чеклист проверки под этот проект |
| `docs/NOTES.md` | я | контекст, решения, открытые вопросы, идеи |

## Маршрут

1. **Разминка.** `tearoff-calendar`.
2. **Архитектуры, первая половина.** MVC, MVP, MVVM + Combine, MVVM SwiftUI, VIPER.
3. **Передышка.** Один пет на выбор, чтобы не выгореть на странах.
4. **Архитектуры, вторая половина.** Clean Swift, Clean Architecture, Redux, TCA, AppKit.
5. **Фундамент.** Тестовый стенд, музей хранилищ, многопоточность.
6. **iOS-петы.** Полка, породы, прогулки, ростер, платформер.
7. **macOS.** Кто в сети, F1-клиент, F1 в менюбаре, матхаммер.
8. **Бэкенд.** Сокращалка, сервер фактов, бот, доска.
9. **Финал.** Аудио, Metal, струны.

## Сквозные правила

- Код пишу сам. Агент ревьюит и делает рутину по образцу. Фичи за меня не пишет.
- Тесты в каждом плане идут этапом, не пунктом «потом».
- В каждом чеклисте ревью есть доступность и обработка ошибок.
- У каждого внешнего API в спецификации назван запасной источник.
- Заготовка это не контракт. Если по ходу понял, что решение было неверным, правлю документ и пишу почему в `NOTES.md`.

## Запас идей, не в плане

Из раннего черновика. Не брать, пока не закончены проекты выше.

- **Офлайн-первый клиент и сервер синхронизации на Go.** Локальная база как источник правды, очередь операций, дельта-синк по ревизиям, конфликты, злой сервер для тестов. Продолжение офлайн-режима из ШМР, самый взрослый проект из всех.
- **Дашборд прогресса на Python.** Скрипт читает чекбоксы во всех `docs/PLAN.md` и рисует общий прогресс по библиотеке.
- **UIKit на сложный интерфейс.** Compositional Layout, diffable data source, кастомные интерактивные переходы.
- **Мини-язык на Swift.** Лексер, парсер, интерпретатор. Enum с ассоциированными значениями и тесты как способ разработки.
- **Проект на C.** Аллокатор, мини-shell или декодер BMP, потом вызвать из Swift через C-interop.
