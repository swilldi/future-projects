# Архитектура

## Коротко

Три слоя с жёсткой границей по потокам. `Synth` это чистый DSP: структуры, буферы, арифметика, без Foundation-аудио, рендерит в массив. `AudioEngineController` на главном акторе владеет `AVAudioEngine`, сессией и `AVAudioSourceNode`, чей колбэк зовёт `Synth.render`. Между ними `CommandQueue`: кольцевой буфер, куда главный поток кладёт команды щипка, а аудиопоток забирает без блокировок. Интерфейс на SwiftUI с `Canvas` для струны.

## Почему так

Аудиопоток нельзя заставлять ждать: пропущенный буфер это щелчок. Поэтому всё общение с ним односторонее и без блокировок, а всё тяжёлое сделано заранее. `Synth` отделён от движка, чтобы его можно было прогнать в тесте на секунду звука и проверить частоту по нулям синусоиды, не запуская аудио вообще. Это единственный способ тестировать DSP.

## Компоненты

**KarplusStrong.** Функции над `UnsafeMutableBufferPointer<Float>`: `excite(buffer, amplitude, position, brightness, rng)` заполняет, `step(voice) -> Float` делает один кадр. Без классов, без аллокаций.

**Voice.** Структура с заранее выделенным буфером максимальной длины (для 110 Гц на 48 кГц это 437 кадров) и текущей длиной. `isActive` снимается, когда скользящая амплитуда ниже порога.

**Synth.** Финальный класс, созданный один раз, владеет массивом из восьми `Voice` и `CommandQueue`. `render(into:frames:)`: сначала вычитывает все команды из очереди и назначает голоса, потом для каждого кадра суммирует активные голоса, делит на восемь, пишет в выходной буфер. Вызывается только из аудиопотока. Помечен `@unchecked Sendable` с комментарием: доступ из двух потоков только через очередь и атомики.

**CommandQueue.** Кольцевой буфер из 64 `PluckCommand` с атомарными индексами головы и хвоста из `Synchronization.Atomic`. `push` с главного потока, `pop` с аудио. Никогда не блокирует, при переполнении `push` возвращает `false`.

**AudioEngineController.** `@MainActor`. Создаёт `AVAudioEngine`, `AVAudioSourceNode` с форматом моно `Float32`, колбэк зовёт `synth.render`. Подписан на уведомления прерывания и смены маршрута. `start()`, `stop()`. Читает `ioBufferDuration` и `outputLatency` для индикатора.

**AudioSessionConfigurator.** Категория, режим, буфер. Одно место.

**StringViewModel.** `@Observable @MainActor`. Параметры слайдеров, `pluck(amplitude:position:)` кладёт команду в очередь, `latencyText`, `activeVoices` через атомик из `Synth`, опрос раз в 100 мс через `Task` с `Clock`.

**StringView.** `Canvas` рисует линию с изгибом от жеста или затухающей волной после щипка. `DragGesture` по струне. Логики звука нет.

## Поток данных

```
жест ──▶ StringView ──▶ viewModel.pluck(amp, pos)
                              │
                              └──▶ commandQueue.push(PluckCommand)     главный поток
                                          │
                                          ▼  (без блокировок)
                    аудиопоток: sourceNode callback ──▶ synth.render
                                          ├──▶ pop команды, назначить голос, excite
                                          └──▶ для каждого кадра: сумма step(voice)
                                                     │
                                                     ▼
                                              выходной буфер
```

## Правила

- Папка `DSP/` не импортирует `AVFoundation`. Только `Synchronization` и стандартная библиотека.
- В `render` и всём, что он зовёт: ни одной аллокации. Проверяется Instruments, Allocations, фильтр по аудиопотоку.
- `Synth` создаётся один раз до `engine.start()`. Пересоздание при смене параметров запрещено: параметры едут в команде.
- Прерывания и маршрут обрабатываются в одном месте, `AudioEngineController`.
- Интерфейс не знает о голосах и буферах, только о командах и числах.

## Что здесь тестируемо

Весь `DSP/`. `KarplusStrongTests`: после `excite` буфер не нулевой; после секунды рендера амплитуда ниже начальной; частота по нулям синусоиды в пределах двух процентов от заданной; нет NaN и бесконечностей; яркость 0,3 даёт меньше энергии в верхних частотах, чем 0,7, грубая оценка через разность соседних отсчётов. `SynthTests`: восемь щипков дают восемь активных голосов; девятый вытесняет; тишина через пять секунд. `CommandQueueTests`: порядок, переполнение, пустая очередь.

## Где ожидать боль

- Первый глюк: `print` в колбэке для отладки. Не делать. Отлаживать через атомарные счётчики, которые читает интерфейс.
- ARC в колбэке: замыкание захватывает `self` класса, каждый вызов делает retain/release. Захватить `Unmanaged` или держать `Synth` в `unowned let`. Замерить разницу.
- Формат узла: моно `Float32`, `interleaved: false`. Ошибка формата это тишина без ошибки.
- `setPreferredIOBufferDuration` это просьба. Реальное значение может быть больше, особенно с Bluetooth-наушниками: там задержка 100 мс и выше, и это не баг.
- Смена маршрута останавливает движок молча. Без обработчика после подключения наушников тишина.
- Тесты DSP на массивах медленные, если рендерить минуту. Секунды хватает.
